

# DeepSeek V3 vs V4：训练 + 推理全维度完整区别
两者共享**DeepSeekMoE稀疏FFN、MTP多Token预测**两大基础组件，但**注意力、残差、优化器、KV缓存、长上下文原生设计、数值稳定性、并行工程**全部发生底层重构，训练侧解决万亿参数震荡，推理侧彻底解决128K以上显存/算力爆炸问题。

## 一、训练阶段核心差异（预训练/微调/分布式）
### 1. 基础架构模块改动
| 模块      | DeepSeek V3                              | DeepSeek V4                              |
| ------- | ---------------------------------------- | ---------------------------------------- |
| 注意力训练主干 | MLA多头潜在注意力（**向量维度压缩**）<br>所有token完整保留，仅压缩K/V向量长度 | Hybrid混合注意力 CSA+HCA+SWA（**序列token压缩**）<br>训练时原生分层压缩token块，远期文本合并摘要KV |
| 残差连接    | 标准Transformer残差<br>超长序列深层梯度易发散、loss震荡    | mHC流形约束超连接<br>残差映射约束在双随机矩阵流形，万亿参数、百万序列训练无loss spikes，无需回滚重启 |
| 优化器     | AdamW（行业通用）<br>超大MoE收敛慢、梯度不稳定            | Muon优化器（全新替换）<br>矩阵正交化+二阶类动量更新，收敛速度提升、专家路由梯度更平稳 |
| MoE路由机制 | 无辅助损失均衡（V3核心创新）<br>静态路由偏置调节负载            | 预判式Anticipatory Routing<br>用历史参数预计算路由索引，专家负载波动大幅降低，减少跨卡通信空闲 |
| 上下文训练策略 | 两阶段扩窗：4K→32K→128K<br>依赖YaRN外推拓展长度，原生上限128K | 原生1M token分层训练<br>浅层HCA全局摘要、中层CSA、顶层全精度，训练阶段直接适配百万长文本，无需后训扩窗 |

### 2. 训练精度、量化与数值系统
1. **V3**
   - 全程FP8混合精度训练，稠密层BF16、MoE激活FP8；
   - KV无原生序列压缩，长序列激活显存随N线性暴涨，64K以上训练显存压力陡增；
   - 仅权重FP8，无FP4感知训练。
2. **V4**
   - **FP4量化感知训练**：路由专家权重原生FP4存储，显存占用减半，不损失精度；
   - KV分层混合精度：RoPE维度BF16，压缩CSA/HCA缓存FP8；
   - mHC约束激活值有界，百万序列下激活值不溢出，降低数值误差。

### 3. 分布式训练与算力、数据
1. **V3**
   - 总参671B，激活37B；训练数据14.8T tokens；
   - 并行：DualPipe流水线并行，仅适配128K以内序列；
   - 完整预训练+微调：278.8万 H800 GPU小时。
2. **V4-Pro**
   - 总参1.6T，激活49B；训练数据规模进一步扩容，长文档/长篇代码占比大幅提升；
   - 并行：MoE张量并行+上下文序列并行，原生拆分1M token序列跨多卡；
   - Muon+mHC大幅减少异常loss，训练容错率显著提升，万亿参数集群稳定运行。

### 4. 训练目标（相同点+细微差异）
- 相同：均使用**MTP多Token预测**，单次预测连续多token，提升收敛与生成速度；
- 差异：V4训练loss新增**长序列检索对齐损失**，优化CSA/HCA压缩块的信息召回精度，解决“大海捞针”长文本遗忘问题。

## 二、推理阶段核心差异（KV缓存、算力、显存、部署、上下文能力）
### 1. KV Cache压缩逻辑（两代最本质分界线）
#### V3-MLA思路：压缩向量，不删减token
对每一个token的K、V向量做低秩降维（kv_lora_rank=512），**历史所有token完整保存**，只是每个KV向量变短。
- 优势：短文本（≤32K）无损、精度极高；
- 致命瓶颈：序列N>128K时，token数量不变，显存、算力随N线性爆炸，无法跑百万上下文。

#### V4-Hybrid混合注意力思路：压缩序列条目，精简token数量
三层并行分支分层处理上下文：
1. **SWA滑动窗口**：最近128 token完整不压缩，保证局部生成细节；
2. **CSA压缩稀疏注意力**：每4个token合并1条KV，Top-k稀疏检索，处理中段几万~几十万文本；
3. **HCA重度全局压缩**：每128个token合并1条摘要KV，作为百万级远期文本索引，计算极廉价。
  **官方实测（1M上下文）**
- V4-Pro单token推理FLOPs = V3.2的27%；KV Cache占用仅V3的10%；
- V4-Flash FLOPs仅V3的10%，KV Cache仅7%。

### 2. 推理计算复杂度
- V3（MLA）：依旧接近标准$O(N^2)$，仅压缩向量降低常数系数，N越大开销暴涨；
- V4（CSA+HCA稀疏）：复杂度被稀疏+分层压缩压制为近似$O(N\sqrt{N})$，百万token推理具备商用可行性。

### 3. 显存占用与冷热缓存工程
1. **V3推理**
   - KV全部常驻GPU HBM，无磁盘分页；
   - 128K已是硬件极限，超过则OOM；
   - 无分层冷热分离机制。
2. **V4推理**
   - **异构KV分页**：热数据（SWA、CSA中段缓存）驻留GPU；远期HCA全局摘要缓存可下沉至系统内存/磁盘；
   - FP4专家权重常驻显存，大幅降低权重基础显存开销；
     单套硬件可稳定承载1M超长上下文，而V3同硬件仅能跑128K上限。

### 4. 长文本检索精度（推理业务价值）
- V3：超过64K后远距离信息召回大幅下滑，MLA仅压缩向量无摘要，远距离依赖建模弱；
- V4：HCA提供全局粗索引，CSA做精细检索，百万token“大海捞针”准确率从84.2%提升至97%，长篇文档、代码库、法律卷宗检索能力质变。

### 5. 部署与量化推理适配
1. V3：仅支持FP8/BF16推理，无原生FP4推理内核；长文本场景必须多卡堆叠；
2. V4：原生FP4权重推理内核，支持vLLM/TensorRT-LLM分层压缩KV优化；提供MegaMoE融合kernel，MoE专家调度延迟更低；同时适配国产昇腾、英伟达全系列GPU。

## 四、核心演进逻辑总结
1. **V3定位**：打磨MoE+MLA的128K最优解，解决**10万级文本**训练推理成本问题，瓶颈是无法突破128K；
2. **V4定位**：架构级重构解决**百万级超长文本**的平方复杂度爆炸问题：
   - 训练端：Muon+mHC稳住万亿参数、百万序列训练不崩溃；
   - 推理端：放弃MLA向量压缩，改用**分层token摘要压缩**，从根源削减KV总量，让百万上下文落地商用；
3. 相同保留模块：DeepSeekMoE稀疏FFN、MTP多Token预测、RMSNorm、SwiGLU激活、RoPE位置编码。
