社区经常提出扩展 vLLM 自定义功能的需求。为了满足这一需求，vLLM 提供了一个插件系统，使用户无需修改 vLLM 代码库即可添加自定义功能。本文档将介绍 vLLM 插件的工作原理以及如何为 vLLM 创建插件。

1. vLLM 插件的工作原理

插件是由用户注册的代码，vLLM 会执行这些代码。鉴于 vLLM 的架构（参见架构概述），尤其是在使用分布式推理和各种并行技术时，可能会涉及多个进程。为了成功启用插件，vLLM 创建的每个进程都需要加载插件。这是通过 vllm.plugins 模块中的 load_general_plugins 函数实现的。该函数在 vLLM 创建的每个进程开始工作之前被调用。

2. vLLM 如何发现插件

vLLM 的插件系统使用了 Python 的标准 entry_points 机制。该机制允许开发者在其 Python 包中注册函数，以供其他包使用。以下是一个插件的示例：

# 在 `setup.py` 文件中
from setuptools import setup

setup(name='vllm_add_dummy_model',
      version='0.1',
      packages=['vllm_add_dummy_model'],
      entry_points={
            
          'vllm.general_plugins':
          ["register_dummy_model = vllm_add_dummy_model:register"]
      })

# 在 `vllm_add_dummy_model.py` 文件中
def register():
    from vllm import ModelRegistry

    if "MyLlava" not in ModelRegistry.get_supported_archs():
        ModelRegistry.register_model("MyLlava",
                                    "vllm_add_dummy_model.my_llava:MyLlava")

有关如何向你的包添加 entry_points 的更多信息，请查阅官方文档。
每个插件包含三个部分：

  1. 插件组（Plugin group）：
    插件组的名称是入口点（entry point）组的名称。vLLM 使用 vllm.general_plugins 作为通用插件的入口点组。这是 setup.py 文件中 entry_points 的键（key）。对于 vLLM 的通用插件，始终使用 vllm.general_plugins。

  2. 插件名称（Plugin name）：
    插件的名称是 entry_points 字典中值的键（key）。在上面的示例中，插件名称是 register_dummy_model。可以通过 VLLM_PLUGINS 环境变量按插件名称过滤插件。如果只想加载特定插件，可以将 VLLM_PLUGINS 设置为该插件的名称。

  3. 插件值（Plugin value）：
    插件值是插件系统中注册函数的完全限定名称。在上面的示例中，插件值是 vllm_add_dummy_model:register，它指向 vllm_add_dummy_model 模块中名为 register 的函数。

3. 支持的插件类型

  1. 通用插件（General plugins，组名为 vllm.general_plugins）：
    这些插件的主要用途是将自定义的、非内置的模型注册到 vLLM 中。通过在插件函数中调用 ModelRegistry.register_model 来实现模型的注册。

  2. 平台插件（Platform plugins，组名为 vllm.platform_plugins）：
    这些插件的主要用途是将自定义的、非内置的平台注册到 vLLM 中。插件函数在当前环境不支持该平台时应返回 None，在支持该平台时应返回平台类的完全限定名称。

4. 编写插件的指南

  1. 可重入性（Re-entrant）：
    在入口点中指定的函数应该是可重入的，这意味着它可以被多次调用而不会引发问题。这是必要的，因为在某些进程中，该函数可能会被多次调用。

5. 兼容性保证

vLLM 保证文档化插件的接口（例如 ModelRegistry.register_model）将始终可供插件用于注册模型。然而，插件开发者有责任确保其插件与其目标版本的 vLLM 兼容。例如，"vllm_add_dummy_model.my_llava:MyLlava" 应与插件目标版本的 vLLM 兼容。在 vLLM 的开发过程中，模型的接口可能会发生变化。
