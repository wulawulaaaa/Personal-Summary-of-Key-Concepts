

# DeepSeek V3 vs V4 长文本推理机制对比
## 一、两代核心路线根本区别
### DeepSeek V3（上限128K tokens）
**核心长文本机制：MLA 多头潜在注意力（维度压缩路线）**
1. **压缩逻辑：对KV向量做特征降维**
   把K、V映射到低维潜空间（`kv_lora_rank=512`），只压缩**向量维度**，不减少序列token数量，所有历史token完整保留，只是每个token的KV向量变短。
2. **配套长上下文方案**
   - 两阶段上下文扩窗训练：4K→32K→128K；
   - 基础滑动窗口局部注意力；
   - 依赖MLA降低KV Cache显存，支撑128K上下文。
3. **瓶颈**
   序列长度N一旦突破128K，显存、算力依然随N线性暴涨，MLA只能压缩向量维度，无法削减token条数，**无法支撑百万级上下文**。

### DeepSeek V4（原生支持1M tokens）
彻底**废弃MLA**，改用**序列维度压缩的混合混合注意力 Hybrid Attention（CSA+HCA+SWA三分支协同）**，这是它能承载远更多内容的核心机制。
V4不再压缩向量维度，而是直接**合并、精简历史token条目**，从根源削减KV Cache总量，把百万上下文推理成本压到可用区间。

## 二、V4支撑超长文本的完整核心机制
### 1. 三层混合注意力堆叠（最核心）

分为三条并行分支，分层处理**近期/中期/远期**上下文，兼顾精度与极致压缩：
#### （1）SWA 滑动窗口注意力（局部高精度）
- 范围：最近128个token**不做任何压缩**，全精度完整注意力；
- 作用：保证当前生成附近的细节、语法、逻辑不丢失，解决长模型局部退化。

#### （2）CSA 压缩稀疏注意力（中期上下文主力）
压缩比例 4:1（每4个原始token合并为1条KV条目）
1. **重叠加权压缩**：不是简单平均，带可学习权重+位置偏置，相邻压缩块重叠，避免段落边界信息断裂；
2. **Lightning Indexer 轻量索引器**：低秩快速匹配；
3. **Top-k稀疏检索**：每个query只取相关性最高的1024（Pro版）压缩条目计算注意力，抛弃无关历史块；
- 定位：处理几万~几十万token的中段文本，平衡细节与显存。



#### （3）HCA 重度压缩注意力（百万级远期全局索引）
压缩比例 128:1（每128个token合并1条全局摘要KV）
- 极激进序列压缩，只保留远距离文本的全局梗概；
- 内部使用稠密注意力，计算极廉价；
- 定位：作为超长历史的**快速检索索引**，CSA/SWA需要回溯远古内容时，先通过HCA快速定位相关区间，再精细读取。

#### 分层排布策略
模型浅层多用HCA处理全局超长背景，中层混合CSA+HCA，顶层+最后几层用完整精度注意力兜底，保证最终推理精度不滑坡。

### 2. 配套辅助长文本稳定机制
1. **注意力Sink 可学习偏置**
   超长序列下注意力权重容易过度分散、模型找不到关键信息；引入可学习logit偏置，约束权重分布，稳定百万token推理聚焦能力。
2. **部分RoPE位置编码**
   只对关键子向量施加RoPE，大幅降低超长序列位置编码计算开销，不丢失位置时序信息。
3. **MQA 多查询注意力简化KV头**
   KV头数量缩减为1，进一步降低KV Cache基础显存开销，配合序列压缩放大收益。
4. **低秩Query投影**
   Query向量做低秩压缩（仅原尺寸15.8%），减少Q-K匹配算力消耗。

### 3. 训练与推理工程优化（支撑百万上下文落地）
1. **mHC 流形约束超连接**
   超长序列+深层Transformer极易出现数值震荡；mHC改造残差连接，解决百万上下文训练、推理时梯度/激活不稳定问题。
2. **FP4量化感知训练**
   MoE专家权重、索引器全程4bit量化，显存占用减半。
3. **异构KV缓存+磁盘分页**
   超长KV Cache可冷热分层，远期HCA压缩缓存存入显存/磁盘，热数据CSA/SWA常驻GPU显存，突破单卡显存物理上限。
4. **两阶段上下文并行训练**
   预训练时逐步扩窗至1M token，让混合注意力原生适配超长文本分布。

## 三、两代长文本能力核心差异总结
| 维度         | DeepSeek V3（128K上限） | DeepSeek V4（1M原生支持）                |
| ---------- | ------------------- | ---------------------------------- |
| 核心注意力      | MLA（向量维度压缩）         | Hybrid混合注意力（序列token压缩 CSA+HCA+SWA） |
| 压缩对象       | 每个token的K/V向量变短     | 直接合并、删减历史token条目                   |
| 远期上下文方案    | 无高效全局摘要，全量存储所有token | HCA 128倍重度压缩做全局索引                  |
| KV Cache效率 | 1M场景显存爆炸无法运行        | 1M上下文KV Cache仅为V3的7%~10%           |
| 计算复杂度      | O(N²)仅小幅降系数         | 通过稀疏+分层压缩，大幅削弱N²增长效应               |

简单概括：
V3靠**压缩向量维度**勉强做到128K；V4放弃该路线，改用**按段落合并token的分层混合压缩注意力**，用HCA做百万字全局摘要、CSA做中段精读、滑动窗口保局部细节，再搭配一整套数值稳定、显存分页工程方案，才实现百万token超长文本推理。
